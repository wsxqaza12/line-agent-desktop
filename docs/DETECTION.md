# AI 安裝偵測與排錯

偵測分成三步：找程式、檢查需要的功能、詢問官方 CLI 的登入狀態。
每個安裝個別顯示位置與結果，不會因為先找到舊版本，就忽略後面的新版。
偵測不呼叫模型，不讀取或複製 OAuth token，也不執行 shell 的個人啟動設定。

## 搜尋範圍

| 環境             | 自動搜尋位置                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| Windows          | 系統／使用者目前登錄的 PATH、程式啟動時的 PATH、原生安裝的 `.local/bin`                          |
| Windows npm      | 預設全域目錄、PATH 與 `NPM_CONFIG_PREFIX` 指定的目錄；依套件 `package.json` 的 `bin` 找入口      |
| Windows 其他位置 | WinGet Links／Claude Code 套件、pnpm 全域目錄、Bun、Volta、Scoop 與舊版本機 npm 位置             |
| WSL              | 最多 8 個非 Docker 環境；各自的 PATH、原生安裝、npm、pnpm、Bun、Volta、asdf、nvm 與 fnm 常見位置 |

這是搜尋位置清單，不代表每種套件管理器都已在全新 Windows 實機驗證。
JavaScript 入口使用隨程式附帶的 Node，原生 `.exe` 直接啟動；不執行 `.cmd` 或 PowerShell 捷徑。
Claude 桌面聊天程式的 WindowsApps 別名會略過，它不是此處使用的 Claude Code CLI。
自訂目錄或其他安裝管理器可用手動選擇。

0.3.1 修正了 npm Claude Code 從 `cli.js` 改成 `bin/claude.exe` 後無法找到的問題。
更新後重新偵測會重新讀 Windows 路徑設定，不必靠重新開機取得新的 PATH。

## 畫面狀態

| 顯示                | 意義與下一步                                                                     |
| ------------------- | -------------------------------------------------------------------------------- |
| 使用這個 AI／已選用 | 程式功能相符，CLI 回報有訂閱登入資訊。實際服務連線與額度仍在開始整理時確認。     |
| 需要登入            | 該環境尚未以訂閱登入，或實際呼叫遭拒。請在相同的 Windows／WSL 環境登入官方 CLI。 |
| 需要更新            | 程式成功回應，但缺少整理流程需要的功能參數。更新該位置的 CLI，再重新偵測。       |
| 尚未確認可用        | 啟動、功能或登入檢查失敗／逾時。細節會指出檢查階段；它不代表一定未安裝。         |
| 未找到              | 先前選用的位置本次沒有找到。原選擇保留供辨認，請選擇新版或手動指定。             |

若 Claude 回報 `401 OAuth access token is invalid`，請在對應環境執行
`claude auth login`，完成後重新偵測。程式不會自動換另一個 AI 或改用 API 金鑰。
官方說明：[Claude Code 安裝排錯](https://code.claude.com/docs/en/troubleshoot-install)。

## 手動選擇

在「AI 助理 → 已安裝，卻沒找到？」選擇 Codex 或 Claude Code，透過檔案選擇器
指定實際的 `.exe` 或 `.js`／`.cjs`／`.mjs` 入口。WSL 可以從
`\\wsl.localhost\發行版名稱\...` 選擇可執行檔。
指定後仍會經過相同的版本、功能與登入檢查。

最多儲存 8 個手動位置。移除手動設定只刪除本工具記住的路徑；如果該位置也能自動找到，
仍會出現在清單。先前所選的項目不會默默換成另一個安裝。

## 範圍與驗證

自動候選上限 24 個。偵測可以停止；約一分鐘會中止尚未完成的外部檢查，
保留已找到的項目與診斷。目錄讀取受作業系統影響，不保證任何故障磁碟都能在固定時間內返回。
不自動探測 UNC 網路分享；WSL 位置可手動指定。

回歸測試涵蓋舊／新 npm 入口、多版本並存、更新後 PATH、中文與空白路徑、
損壞套件、桌面別名、WSL 多環境記錄、檢查逾時與取消、失效登入、遺失的選擇及手動設定保存。
其中安裝目錄組合多為合成測試；實機結果與尚未驗證的項目列在[驗證紀錄](VALIDATION.md)。
